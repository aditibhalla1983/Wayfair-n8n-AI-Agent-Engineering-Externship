Consumer Trend Discovery AI Agent — Design Document

Architecture: n8n + OpenRouter Chat Models + External Product and Trend APIs + Cloudflare Workers AI

Status: Prototype

Basis: Uploaded n8n workflow configuration; no live execution was performed.

1. System Overview

The Consumer Trend Discovery AI Agent transforms a rug-category request into a structured, image-rich market intelligence report. It combines product listings, social text signals, blog expertise, and market content to discover aesthetic micro-segments and generate illustrative moodboards.

Design objective: Turn fragmented category information into structured insights and visual inspiration through a modular AI workflow.

2. Workflow and Responsibilities

| Stage | Component | Responsibility |

|---|---|---|

| 1 | Input validation | Parse category and optional focus |

| 2A | Product retrieval | Fetch and normalize Amazon records |

| 2B | Social and blog retrieval | Collect supporting evidence and reference images |

| 3 | AI processing | Classify, normalize, and discover micro-segments |

| 4 | Moodboard generation | Generate illustrative images |

| 5–6 | Report writing | Extract expertise and create report sections |

| 7 | Output | Assemble, check, and package HTML |

3. Step-by-Step Workflow

Stage 01 — Input Validation

| Item | Description |

|---|---|

| Purpose | Accept a rug category and optional focus, then return structured input for retrieval. |

| Technology | Python parser + n8n IF node |

| Input | `Outdoor Rug, focus: weather-resistant weaves` |

| Output | `selectedCategory`, `categoryKey`, `focus`, and validation flags. |

Nodes: `User Enters the Category` → `InputParser1` → `CategoryValidator1`; invalid input routes to `Error Response1`.

Processing:

- Normalizes capitalization and whitespace.

- Matches configured category phrases and extracts text after `focus:`.

- Routes greetings and unrecognized categories to guidance.

Stage 02A — Amazon Product Retrieval

| Item | Description |

|---|---|

| Purpose | Retrieve product records from the external backend and normalize them for analysis. |

| Technology | HTTP GET + JavaScript + IF node |

| Input | Category key, optional focus, and a requested limit of 10 products. |

| Output | `amazonProducts`, `totalProducts`, and `scrapedAt`. |

Nodes: `Fetch Amazon Products` → `Has Amazon Products?` → `Reshape Amazon Response`.

Processing:

- Calls `/api/products/amazon`; n8n does not scrape Amazon directly.

- Preserves product URL, name, price, details, pattern, image URL, rating, and review count.

- Uses a 30-second request timeout and a product-count branch.

Stage 02B — Social and Blog Retrieval

| Item | Description |

|---|---|

| Purpose | Collect social captions, hashtags, blog expertise, and market research content. |

| Technology | HTTP requests + JavaScript |

| Input | The selected category key. |

| Output | Grouped social/blog records, selected images, source counts, and caption-derived context. |

Nodes: `Get Category Key` → parallel fetch nodes → `MergeAPIData` → `Merge Social Data1` → `Merge Image Analysis`.

Processing:

- Retrieves Instagram, Pinterest, blog, and market records through backend APIs.

- Selects up to three available Base64 images from each social platform.

- Counts hashtag frequency, retains the top 20 hashtags, and prepares text context.

Stage 03 — AI Classification and Trend Discovery

| Item | Description |

|---|---|

| Purpose | Turn raw evidence into comparable product attributes and two to three aesthetic micro-segments. |

| Technology | OpenRouter chat models configured with `openrouter/free` |

| Input | Product records, selected category, and social/blog text context. |

| Output | Filtered products, normalized attributes, summaries, and `microSegments`. |

Nodes: `Judge Product Category` → `Remove Invalid Products` → `Standarized Details` → `Save Standarized Data` → `Identify Top Trend` → `Save Trend List`.

Processing:

- Retains category matches whose confidence is not low.

- Normalizes size, color, material, pattern, style, pile height, and price bucket.

- Defines segment identity, palette, materials, target rooms, positioning, evidence signals, and image keywords.

Stage 04 — Moodboard Generation

| Item | Description |

|---|---|

| Purpose | Create illustrative moodboards from the discovered style directions. |

| Technology | OpenRouter + JavaScript + Cloudflare Workers AI |

| Input | Micro-segment description, palette, materials, room context, and image keywords. |

| Output | `generatedImages`, `totalImages`, and `failedImages` for report embedding. |

Nodes: `Split Segment for Images` → `Check Segment Exists` → `Generate Image Prompt` → `Clean Prompt` → `Generate Image` → `Encode to Base` → `Collect All Images`.

Processing:

- Creates a flowing prompt describing the rug, setting, composition, and lighting.

- Normalizes text and caps the image request prompt at 2,000 characters.

- Calls `@cf/black-forest-labs/flux-1-schnell` with four steps and a 120-second timeout.

Stage 05–06 — Knowledge Extraction and Report Writing

| Item | Description |

|---|---|

| Purpose | Convert source evidence and structured analysis into eight report sections. |

| Technology | OpenRouter writing agents + deterministic scope-generation code |

| Input | Normalized product data, micro-segments, blog knowledge, social context, and image counts. |

| Output | HTML fragments for the eight report sections. |

Nodes: `Blog Kowledge Extractor` → `Parse Blog Knowledge` → `Scope Generator Node` → sequential report-writing agents.

Processing:

- Extracts material, sizing, style, buyer, and care knowledge from blogs.

- Generates the scope and sample counts in code.

- Writes the executive summary, market research, category, attributes, visuals, risks, and recommendations.

Stage 07 — HTML Assembly and Output

| Item | Description |

|---|---|

| Purpose | Combine the sections and images into a downloadable report. |

| Technology | JavaScript + HTML/CSS + Base64 binary packaging |

| Input | Section HTML, category/date metadata, generated images, and social-reference images. |

| Output | `{category_slug}_trend_report_{YYYY-MM-DD}.html` with MIME type `text/html`. |

Nodes: `Collect All Sections` → `Assemble HTML Report` → `Section Validator1` → `Download Final Report`.

Processing:

- Applies the report stylesheet and replaces image placeholders.

- Records section-keyword matches, embedded image count, and the closing HTML tag.

- Packages the HTML in `binary.data` with file metadata and validation results.

5. Prototype Boundaries and Safeguards

- Social observations are caption- and hashtag-derived, not direct image analysis.

- Product listing frequency is not sales share; social mentions do not independently prove purchase demand.

- Calculate distributions from validated records and show unavailable states when evidence is missing.

- Preserve original source URLs, collection dates, and market definitions.

- Add consistency and completeness checks that can stop or flag export.

- The export contains an inline Cloudflare bearer credential. Rotate it and use managed credentials. No credential is reproduced here.

- The supplied workflow has no Wayfair retrieval/comparison nodes, although the earlier Outdoor report contains an additional Wayfair opportunity section.

Summary

The prototype connects category input, evidence retrieval, classification, trend synthesis, moodboard generation, and report assembly. Each stage has a distinct responsibility, making the workflow easier to inspect, debug, and extend. Production readiness requires stronger evidence checks, secure configuration, reliable item-wise processing, and validation that can prevent incomplete or misleading output.
